# 刷机指南（零基础版）

> 目标读者：**没写过代码**，但会用 GitHub、会用编程器（CH341A 之类）、会用电烙铁。
>
> 照着做大约 **1.5 小时**（大部分时间在等 GitHub 编译）。
> 全程 **不需要串口线、不需要 TFTP、不需要碰 U-Boot 菜单**。

---

## 开始之前，先确认三件事

### ① 你的路由器是水星 D121G

翻到机器背面看标签。本项目只在 **水星 D121G** 上验证过，规格是：

- 主控 MT7620DA，5G 是 MT7612EN，交换芯片 RTL8367S
- **3 个千兆网口**（不是 4 个口！）
- 原厂 Flash **2MB**，型号 Eon EN25QH16

> ⚠️ 水星还有 D12G / D12GB 等型号，**网口数和交换芯片不一样**。
> 型号不对就别刷，会变砖。

### ② 你手上有这些东西

| 东西 | 说明 |
|---|---|
| CH341A 编程器 + SOP8 夹子/转接座 | 读原厂片用 |
| **新的 W25Q128（16MB）** | 原厂 2MB 装不下 OpenWrt，必须换 |
| 电烙铁 / 热风枪 | 拆焊 flash |
| 电脑（Windows 就行） | |
| GitHub 账号 | |

### ③ ⚠️ 关于编程器的电压（很容易忽略）

CH341A 那种**黑色小板**默认是 **5V**，而 25 系列 flash 是 **3.3V**。

- 如果你的板子上有 3.3V/5V 跳线或开关，**拨到 3.3V**
- 有些黑色板要自己改（焊掉一个电阻、或换 LDO），动手前先查你那款
- 白色/绿色板通常是 3.3V

读取时电压不对可能读出错数据，写入时可能损坏芯片。

## 第 1 步：备份原厂 Flash（**最重要，千万别跳过**）

这一步是为了拿到**你这台机器独有的 WiFi 校准数据**。每台机器的校准值和 MAC 地址都不一样，
**丢了 WiFi 就废了**（信号弱、或者根本不出信号）。

### 1.1 把原厂 flash 拆下来

用热风枪或烙铁把原厂那颗 2MB 的 SOP8 芯片拆下来。

> 如果不想拆，用 SOP8 夹子在线夹也行，但**在线读取常常读不准**，
> 因为主控会给 flash 供电、干扰信号。**强烈建议拆下来读**。

### 1.2 读出来

按你的编程器软件操作（NeoProgrammer / AsProgrammer / flashrom 都行）：

1. 芯片型号选 **EN25QH16**（或自动识别）
2. 点**读取**
3. **读两遍**，对比两次结果是否一致 —— 不一致说明接触不良，重新夹好再读
4. 保存为 `stock.bin`

**检查大小必须是 `2,097,152` 字节（正好 2MB）**。不是这个大小就是读错了。

### 1.3 多备份几份

`stock.bin` 至少存三个地方（电脑、U 盘、网盘）。
**这个文件是你唯一的后悔药** —— 没有它，你的路由器再也回不到原厂状态。

## 第 2 步：在 GitHub 上编译固件

### 2.1 Fork 仓库

打开 👉 **https://github.com/Huang22333/openwrt-mercury-d121g**

点右上角 **Fork** → 点 **Create fork**。

现在你账号下有一份自己的副本了。

### 2.2 （可选）改配置

**如果你不需要中文界面、也不加别的软件包，这一步可以直接跳到 2.3。**

想改就点开 `configs/d121g_defconfig`，点右上角铅笔图标编辑。

**想加中文界面**，把文件末尾这几行的 `#` 去掉：

```
CONFIG_LUCI_LANG_zh_Hans=y
CONFIG_PACKAGE_luci-i18n-base-zh-cn=y
CONFIG_PACKAGE_luci-i18n-firewall-zh-cn=y
CONFIG_PACKAGE_luci-i18n-package-manager-zh-cn=y
```

> 也可以先不编进去，等系统跑起来后联网装（见第 6 步）。**推荐后者，省事。**

改完点 **Commit changes**。

### 2.3 开始编译

1. 点你仓库上方的 **Actions** 标签
2. 左边选 **Build OpenWrt for Mercury D121G**
3. 右边点 **Run workflow** → 绿色按钮
4. 等 **40~60 分钟**

状态说明：

- 🟡 **黄色转圈** = 正在编译，耐心等
- ✅ **绿色对勾** = 成功
- ❌ **红色叉** = 失败（去仓库提 issue，附上运行的链接）

> 改动 `configs/`、`patches/`、`dts/` 下的文件会自动触发编译，不用手动点。
> 只想重新编一次、没改任何文件，就用 2.3 的手动方式。

### 2.4 下载产物

编译成功后，点进那次运行，**拉到底部的 Artifacts**，下载 `openwrt-mercury_d121g.zip`。

解压，你会看到：

```
openwrt-ramips-mt7620-mercury_d121g-squashfs-sysupgrade.bin   ← 要的就是这个
openwrt-ramips-mt7620-mercury_d121g-initramfs-kernel.bin
openwrt-ramips-mt7620-mercury_d121g.manifest
sha256sums
```

> ⚠️ **Artifact 只保留 30 天，赶紧下载存好。**
>
> ⚠️ 只有**登录你自己的 GitHub 账号**才能下载，别人（未登录）打不开。

## 第 3 步：生成刷机镜像

编译出来的是**原始固件**，还不能直接写进芯片。要用工具转一下，
把「你的原厂数据」和「新固件」拼成一片 16MB 的完整镜像。

### 3.1 装 Python

去 👉 https://www.python.org/downloads/ 下载安装。

**安装时务必勾选 ☑ Add Python to PATH**（在第一个安装界面的底部）。
忘了勾选就卸载重装。

### 3.2 放好三个文件

新建一个文件夹，比如 `D:\d121g`，把这三个文件放进去：

```
D:\d121g\
├── make_full_flash.py              ← 从仓库 tools/ 目录下载
├── stock.bin                       ← 第 1 步备份的
└── openwrt-ramips-mt7620-mercury_d121g-squashfs-sysupgrade.bin   ← 第 2 步下载的
```

> `make_full_flash.py` 在仓库的 `tools` 文件夹里，点进去 → 点 **Download raw file**。

### 3.3 运行

在 `D:\d121g` 文件夹里，**按住 Shift + 鼠标右键** → 「在此处打开 PowerShell 窗口」
（Win11 是「在终端中打开」）。

输入下面这行，然后回车：

```
python make_full_flash.py stock.bin openwrt-ramips-mt7620-mercury_d121g-squashfs-sysupgrade.bin
```

正常会看到五步流程，最后 **5 个 ✓**：

```
 第 1 步：读原厂 2MB 备份
  ✓ WiFi 校准头正确（20 76）
  ✓ 板型串确认：devModel:D121G
 第 2 步：给 U-Boot 打 1 字节补丁
  ✓ 自检通过：全片只改了这 1 个字节
 第 3 步：生成固件段
 第 4 步：拼成 16MB 全片
 第 5 步：自检
  ✓ U-Boot 补丁（0x2338 = fe）
  ✓ WiFi 校准原样保留
  ✓ 假 LZMA 头（13 字节）
  ✓ 真 LZMA 载荷（0x15200 = 6d）
  ✓ squashfs 魔数（0x295000 = hsqs）
```

生成 `d121g_full_16m.bin`（正好 16,777,216 字节）+ 一个 `.sha256` 校验文件。

**如果报错**，工具会用人话告诉你哪不对，比如：

| 报错 | 意思 |
|---|---|
| `原厂备份必须是 2MB` | 你把 sysupgrade.bin 当原厂备份传了，两个参数传反了 |
| `找不到 D121G 的板型串` | 这份备份不是 D121G 的，别用 |
| `找不到那个 2MB 上限常量` | 你的 U-Boot 版本和本项目验证过的不一样，**别硬刷**，去提 issue |

---

## 第 4 步：写入新芯片

1. 把**新的 W25Q128** 装到编程器上
2. 芯片型号选 **W25Q128**（或自动识别）
3. **擦除**（Erase）
4. **写入** `d121g_full_16m.bin`
5. ⚠️ **写完必须点「校验 / Verify」**，等它显示校验通过
6. 如果写入或校验失败 → 重新擦除再来一次

> 写入 16MB 比读 2MB 慢，耐心等，中途别拔。

---

## 第 5 步：焊上去，开机

1. 把写好固件的 W25Q128 焊回板子（注意方向，芯片上有个圆点/缺口标记 1 脚）
2. 检查有没有虚焊、连锡
3. 插网线到**任意一个 LAN 口**（不是 WAN 口）
4. 上电

等 **1~2 分钟**，然后：

- 电脑网卡设成「自动获取 IP」
- 浏览器打开 👉 **http://192.168.1.1**

能看到 LuCI 登录页就成功了 🎉

**首次登录**：直接点 Login（默认没有密码）。

> 建议第一件事就去 **System → Administration** 设个密码。

### 如果打不开

| 现象 | 排查 |
|---|---|
| 网口灯不亮 | 焊点问题，重新补焊 |
| 灯亮但拿不到 IP | 换个 LAN 口试试；电脑设成静态 IP `192.168.1.100`，掩码 `255.255.255.0` |
| 能 ping 通但打不开网页 | 清浏览器缓存、换浏览器、用无痕窗口 |
| 完全没反应 | 芯片方向焊反了，或者写入时没校验 |

系统能上网的话（WAN 口接到上级路由），SSH 或 LuCI 的终端里执行：

## 以后的升级

**不需要再拆机、不需要编程器。** 系统里直接升级：

**LuCI**：System → Backup / Flash Firmware → Flash image，选**同一个** `...sysupgrade.bin` 文件。

**命令行**：

```sh
sysupgrade -n /tmp/openwrt-ramips-mt7620-mercury_d121g-squashfs-sysupgrade.bin
```

> 注意：这里用的是**编译出来的原始** `sysupgrade.bin`，
> **不是** `d121g_full_16m.bin`（那个是给编程器用的全片镜像）。

> ⚠️ 升级前建议先备份配置：System → Backup / Flash Firmware → Generate archive。

## 想刷回原厂

用编程器把第 1 步备份的 `stock.bin` 写回**原厂那颗 2MB 芯片**，
再把 2MB 芯片焊回去就行。

> 本项目不会改动原厂芯片 —— 你换的是新的 16MB 片，原厂片原封不动留着，随时能回去。

## 常见问题

**Q: 一定要换 flash 吗？**
A: 一定。原厂只有 2MB，OpenWrt 内核加根文件系统装不下。

**Q: 我读原厂 flash 的时候读出来全是 FF / 00？**
A: 接触不良。重新夹好，或者把芯片拆下来读。也检查编程器电压跳线。

**Q: 编译失败了怎么办？**
A: 到 👉 https://github.com/Huang22333/openwrt-mercury-d121g/issues 提 issue，
把 Actions 里那次红色运行的链接贴上，说明卡在哪一步。

**Q: 别人的固件包能拿来直接刷吗？**
A: **不能。** 里面含的是**他那台**的 MAC 和 WiFi 校准。
所以本项目给的是「工具 + 编译流程」，让每个人生成自己专属的镜像。

**Q: 能刷到别的路由器上吗？**
A: 不能。这份固件是专门给 D121G 的（分区布局、网口映射、交换芯片驱动都是针对它的）。

**Q: 5G 和 2.4G 都能用吗？**
A: 能。已经在你机器上实测过，两个频段都正常工作。

## 附：技术细节（不用看懂，出问题时给懂的人看）

- 主控 U-Boot 会把内核加载到 `0x80001000`，而 OpenWrt 内核链接在 `0x80000000`，
  差 `0x1000` 导致死机 → 用官方 `relocate-kernel` 桩解决
- 固件分区必须从 `0x15000` 开始（不是 U-Boot 实际读的 `0x15200`），
  否则 `mtdpart` 的对齐检查会让整个分区变只读
- 需要 `CONFIG_MTD_SPLIT_LZMA_FW=y` 才能拆分 kernel/rootfs
- 详细推导见仓库 `docs/` 目录
